> 데이터 모델링의 이해 개념 정리

## 데이터 모델링 유의점

- 중복
- 비유연성
  - 프로세스와 연계성을 낮춰 수정범위 최소화
- 비일관성

---

## 스키마 3단계

### 1. 외부 스키마

    - 여러 사용자 관점으로 구성 (View)
    ex) 학생은 성적만 조회/교사는 학생들의 성적 조회/행정직원은 주소를 조회

### 2. 개념 스키마

    - 모든 사용자 관점으로 구성
    ex) 학생 테이블에는 성적, 주소가 구성됨

### 3. 내부 스키마

    - 저장 관점
    ex) 디스크에 저장, 인덱스 사용

---

## 엔터티

### 엔터티 작성 순서

도출 -> 배치 ->관계 기술

### 배치

- 중요할수록 왼쪽, 상단

### 엔터티 특징

- 다른 엔터티랑 관계가 있어야함. 근데 통계성, 코드성 엔터티는 관계 없어도 됨
- 인스턴스 (row)는 **_2개 이상_** 이어야 함.
- 한 개의 엔터티는 2개 이상의 속성 가짐
- 속성은 하나의 속성값을 가짐 (최소 단위가 속성임)
- 업무 프로세스에 의해 이용

### 발생 시험에 따른 엔터티 분류

- 기본 엔터티 (Fundametal)
  - 회원, 상품
- 중심 엔터티 (Main)
  - 주문
- 행위 엔터티 (Active)
  - 주문 이력, 결제 이력

### 엔터티 작명

- 약어 x

## 정규화

> 논리 데이터 모델 상세화 과정의 대표적인 활동

### 1차 정규화

- 원자값
- 하나의 속성에는 하나의 속성값만 있어야함
- 쉼표로 구분 x

### 2차 정규화

- 부분 함수 종속 제거
- 다른 속성이 기본키 일부에만 종속x

### 3차 정규화

- 이행 함수 종속 제거
- 기본키가 아닌 일반 속성에 종속

## 속성

### 기본속성

- 업무분석을 통해 바로 정의

### 설계 속성

- 설계하면서 도출

### 파생 속성

- 빠른 조회를 위해 미리 계산하여 저장하는 속성

### 속성 작명

- 전체 데이터 모델에서 유일성 확보
- 약어 x
- 서술식 x

## 도메인

- 속성의 범위, 데이터 타입, 제약사항을 속성의 **_도메인_** 이라고 함.

## 관계

### 연관관계

- 존재에 의한 관계
- 실선
- 멤버 변수로 선언

### 의존관계

- 행위에 의한 관계
- 점선
- 오퍼레이션에서 파라미터로 이용

### 표기법

- 관계명
- 관계차수
  - 1:N, N:M
- 관계선택사양
  - 필수/선택

### 관계 도출 확인 사항

- 연관규칙
- 조합
- 규칙
- 동사

## 식별자

### 식별자 종류

1. 주식별자/보조식별자
   - 보조식별자도 유일하게 구분할 수 있으니 대표성이 없음
2. 내부식별자/외부식별자
   - 엔티티 내부에서 스스로 생성->내부
3. 단일식별자/복합식별자
   - 학생ID와 과목ID로 성적 알 수 있음 -> 복합식별자
4. 본질식별자/인조식별자
   - 주민번호 -> 본질, 회원번호 1,2,3번 -> 인조
   - 인조식별자
     - 실제 중복을 막기 힘듬
     - 추가적인 인덱스 필요

### 식별자/비식별자 관계

1. 식별자 관계
   - 부모의 FK가 자식의 주식별자에 포함
   - sql 조인화를 최소화 가능
2. 비식별자 관계
   - 부모의 FK가 자식의 주식별자에 포함x
